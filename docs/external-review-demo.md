# External client review demonstration

Shareout helps people share work beyond the AI workspace where it was made. The client needs an ordinary browser, not an AI subscription or membership in the publisher's AI team. Viewing and commenting permissions are separate: a viewing link alone must never be presented as a commenter invitation.

## Story

Use only the fictional Daybook scheduling proposal. Label the two sides **Developer / Cline** and **Client / browser**. Do not portray the staged client role as a real customer testimonial.

1. The developer asks Cline to publish a proposal for a client outside the team. Cline uses the Shareout skill and the isolated demo workspace.
2. The client opens the recipient link in an ordinary browser, compares the current and proposed experience, and tries rescheduling the appointment.
3. Using an explicitly granted commenter invitation, the client asks: “Can we limit changes to the organiser and require 24 hours’ notice?” Show any required Shareout reviewer authentication honestly; no AI-team account is needed.
4. Cline reads that comment, updates the two decisions, and publishes a revision using the current base version.
5. The client refreshes the same viewing link and sees the agreed decisions. Only resolve the review thread after implementing the request.

Target 60–90 edited seconds. Trim idle time, label cuts, preserve actual host interactions, and keep credentials and unrelated account details out of frame. Capture the recipient result as a screenshot. Demonstrate link revocation separately if needed for acceptance, rather than making it the main product story.
